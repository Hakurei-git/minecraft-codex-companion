# Minecraft Codex Companion 安装版

[English](README.md)

## 选择哪个版本

- `MinecraftCodexCompanion-Setup.exe` 是普通用户入口。它是单文件安装器，包含 Companion 本地控制服务、Dashboard、Forge 1.20.1 模组和配置程序；不要求用户安装 Node.js 或手工构建 JAR。
- `MinecraftCodexCompanion-AgentKit-v0.1.5.zip` 是可选的 AI 接入包。只有在需要把 Minecraft 操作 Skill/MCP 配置导入 Codex、Claude、反重力或其他 AI 客户端时才下载；它不能替代 EXE 和游戏侧模组。

EXE 不包含 Minecraft 账号、Minecraft 游戏本体或 HMCL 登录状态。首次配置前，请准备能够正常进入 Forge 1.20.1 世界的 HMCL 环境。当前完整实机验收基于 HMCL 单人世界。

## 可选的已适配龙模组

- Book of Dragons（`bookofdragons`），实机测试版本为 `bookofdragons-1.31-1.20.1`。
- Saints Dragons（`saintsdragons`），实机测试版本为 `saintsdragons-0.8.2+forge-1.20.1-alpha`。

两个适配器均支持状态/归属识别、喂食、治疗、驯服、照顾龙蛋、跟随/等待、上龙/下龙、共享骑乘、飞行、降落、召回、地形脱困和协助战斗。第三方模组 JAR 不随安装器分发；请先把兼容版本放进 HMCL 源实例，创建隔离实例时会保留已有模组。除上述实测版本外，其他版本目前不保证兼容。

## 安全与隐私

- 发布安装器只负责校验并原子展开透明的多文件便携包；安装后的主 EXE 不会注入或修改其他 EXE。
- 运行时不包含、生成或调用 PowerShell/命令行脚本，不下载可执行代码，也不申请管理员权限。
- 安装实例只复制玩家选择的 Forge 1.20.1 实例配置、模组和版本文件；不会复制世界、日志或截图。
- API Key 由当前 Windows 用户的 DPAPI 加密。DPAPI 操作由职责单一的本地辅助程序完成，不拼接或执行脚本。
- `portable-manifest.json` 记录所有文件和构建输入的 SHA-256。程序启动时会校验关键文件，校验失败即停止。
- 发布包不包含 API Key、桥接令牌、本地运行状态、世界、聊天记录或构建电脑的绝对路径。
- `scripts/scan-portable.ps1` 只在本机校验哈希、签名和杀毒结果，不上传文件、哈希或扫描结果。
- 任务运行状态只写入目标电脑的本机状态目录；控制服务或桥接重启后会重新挂接 Minecraft 中的当前步骤，不把任务内容发往额外服务。

商业/公开分发版本应使用受信任的 Authenticode 代码签名证书和 RFC 3161 时间戳。未签名的本地开发包即使内容安全，也可能因为缺少发布者信誉而被部分杀毒软件提示。

## 首次使用

1. 运行 GitHub Release 中的 `MinecraftCodexCompanion-Setup.exe`；它会校验并安装完整便携运行时，然后自动打开配置程序。
2. 后续可从开始菜单或安装目录直接运行 `MinecraftCodexCompanion.exe`。程序会同时启动本机控制服务，正常时 Dashboard 地址为 `http://127.0.0.1:8765`。
3. 选择本机 HMCL 启动器、Minecraft 根目录以及 Forge 1.20.1 源实例。程序只在有限的用户目录中自动发现；结果不正确时点击“浏览”手工选择。
4. 填写新隔离实例名、游戏玩家名和 NPC 名称。玩家名必须与进入世界时的名称一致，否则自由聊天过滤和物品交付可能无法找到玩家。
5. 选择继承现有人格或设置 Minecraft 专用人格；需要时导入 `128x64` PNG 皮肤。NPC 名称和皮肤以后仍可更换。
6. 点击“一键准备并启动”。程序会创建隔离实例并写入所需模组，不复制原实例的世界、日志和截图。
7. 在 HMCL 中选择新建实例并进入一个测试世界。第一次测试不要使用重要存档。
8. 回到 Dashboard，确认同伴列表已出现 NPC。可先使用“召回”和“跟随”验证连接，再开始采集或建筑任务。

## 日常使用

1. 需要游玩时启动 `MinecraftCodexCompanion.exe`，再通过 HMCL 进入 Companion 隔离实例；不测试时可以关闭 Minecraft 以释放内存。
2. 在 Dashboard 的“AI 生成服务”中选择 Codex、Claude 或反重力响应端，配置自由聊天的玩家名，并按需要启用自由聊天。
3. 在游戏按 `T` 直接输入消息。自由聊天启用后无需 `@`；关闭时仍可使用 `@codex`、`@claude`、`@多代理` 或 `@反重力` 定向发送。
4. 任务开始、关键进度、失败原因和最终完成结果会通过 NPC 的游戏聊天发送。需要立即停止时输入“停”“急停”或 `stop`，该命令由本机直接处理。

常见中文任务示例：

```text
跟着我
给我找 16 个肉
制作一把钻石镐并交给我
建造一个小屋
继续上次失败的建造
报告你的生命、饱食度、装备和当前任务
```

AI 自由聊天可以跟随中英文；固定界面和本地确定性动作短语当前以简体中文为主。复杂英文动作建议启用智能 AI。

## Codex / Claude / 反重力

- 普通聊天和动作指令可直接在游戏中发送，不要求使用 `@`。
- 响应端可选“Codex + Claude 协作”；两个无 Minecraft 工具的顾问并行规划，只有 Codex 协调器可以执行动作并发送一条最终回复。也可在 `T` 聊天中用 `@多代理` 临时触发。
- Codex/Claude 兼容 API 在高级控制台中配置；Key 不写入便携包或普通配置文件。
- 反重力 MCP 配置会先备份再合并，不会覆盖其他 MCP 设置。
- 反重力按任务列表中的完整标题精确绑定同一条现有对话并继承既有人格；绑定后固定保存会话 ID，不会因打开其他对话、程序更新或重启而漂移。默认不按本地估算的轮数或字符数提前换会话，只有反重力明确报告真实上下文容量已满时才创建带 `[MC-n]` 序号的新会话并重试当前消息；本地上限只在用户显式配置时生效。长任务分配后结束当前回合，由游戏继续执行并主动发送一次终态，不需要持续轮询。
- 玩家能看到的闲聊、进度、失败说明和最终回复必须通过 `mc_chat` 发送。

### 智能 AI 与本地稳定模式

- 开启“智能 AI”后，自由表达和组合目标会先在设定的单次 token 预算内转换为结构化任务；本地执行器仍会检查玩家、NPC、材料、权限、配方和交付目标。
- 关闭“智能 AI”后，不调用模型做任务规划，也不消耗这一步的 token。跟随、召回、停止、已支持的采集/制作/交付、建筑菜单和深挖钻石动作链仍由本机确定性解析器执行。
- “自由聊天”是独立开关。关闭智能规划不等于关闭 AI 闲聊；反过来，关闭自由聊天也不会禁用明确的定向命令。
- 智能规划只产生结构化任务，不允许玩家聊天或导入内容要求读取本机文件、泄露 Key、访问任意 URL、绕过权限或执行代码。

开启智能 AI 会为复杂或本地无法识别的动作额外调用一次模型，因此会增加输入和输出 token 消耗。`单次输出预算`只限制规划输出，不代表限制全部计费；显式多代理通常还要分别调用顾问和协调器，所以比单代理更耗 token。自由聊天回复也会独立消耗 token。关闭智能 AI 只表示已识别的本地动作链不消耗规划模型 token，不代表仍然开启的自由聊天不消耗 token。

## 常见问题

**Dashboard 打不开：**先启动已安装的 `MinecraftCodexCompanion.exe`，再访问 `http://127.0.0.1:8765/api/health`。如果端口被其他程序占用，关闭冲突程序后重启 Companion。

**Dashboard 在线但看不到 NPC：**确认已经进入安装器创建的 Forge 1.20.1 实例和世界；检查模组版本与桥接状态，然后使用“召回”。

**游戏聊天没有回复：**检查自由聊天是否开启、玩家名是否完全正确、响应端是否可用。反重力还必须运行并绑定正确的完整会话标题。

**AI 只答应却没有动作：**在任务列表确认是否真的创建了任务。复杂表达可启用智能 AI；使用外部 AgentKit 时还要确认 AI 已连接 MCP 并取得 NPC 控制租约。

**任务中断或建造重新开始：**先查看失败原因和恢复提示。清理阻挡或补齐材料后输入“继续建造”，让执行器恢复原检查点，不要创建新的同名任务。

**中文变成问号或乱码：**确保外部 AI 通过 `mc_chat` 发送有效 UTF-8/Unicode。明显损坏的内容会被本机拒绝，不会继续刷入游戏聊天。

**Minecraft 内存占用高：**只在实际测试或游玩时启动游戏；关闭世界和 HMCL 游戏进程不会删除 Companion 配置。控制服务本身可单独保留，也可以一起退出。

## 搬到另一台电脑

复制原始 ZIP 或完整解压目录，在新电脑重新选择启动器与 Minecraft 路径。不要复制 `%LOCALAPPDATA%\MinecraftCodexCompanion`，其中包含目标电脑生成的桥接令牌、加密配置和运行日志。

## 发布前本地检查

```powershell
npm run release:portable
```

`release:portable` 会先构建，再执行本机杀毒、完整性和透明运行时检查；任何威胁、可疑对象、扫描错误或完整性错误都会让发布命令失败。扫描报告保存在构建目录的 `SECURITY-REPORT.json`。

正式对外发布时，把代码签名证书指纹放在当前进程的 `MC_COMPANION_SIGNING_CERT_SHA1` 环境变量中，再运行 `npm run release:portable:signed`。证书、私钥和指纹不会写入源码或发布包。
